# Architecture — QA MultiAgents for AR & CR

## Base layer (Regnology doctrine-product)

This project starts from the **product desk** in [RAF/doctrine-product](https://bitbucket.regnology.net/projects/RAF/repos/doctrine-product/browse) (branch `team/agile-reporter`).

The desk is four agents any product team can switch on:

| Greeting | Profile | Role |
|----------|---------|------|
| Hey Olga | `onboarding-olga` | One-time onboarding interview; writes pack/settings |
| Hey Clara | `clerk-clara` | Find/read tickets (customer, release, product item) |
| Hey Qata | `qa-qata` | QA / test-run review; verify fixes against evidence |
| Hey Rela | `release-rela` | Release readiness, notes, publish, announce |

Wiring is generated by doctrine-product `skills/setup/regulatory-pack-setup/scripts/install_cursor_wiring.py` into Cursor rules/agents and mirrored under this repo’s `.cursor/` and `.agents/skills/`.

Shared desk skills: `product-desk-consult`, `product-desk-comment`, `product-desk-capability`, `product-desk-tickets`, `product-desk-release-notes`, plus auto-route rule when the user does not say `Hey <name>`.

## Agile Reporter QA extensions (added on top)

Without replacing doctrine-product infrastructure, this project adds **Cursor-native AR QA** skills and rules:

| Skill / rule | Purpose |
|--------------|---------|
| `ar-qa-browser-visible` | Permanent **visible browser**; slow type; narrate OPEN/TYPE/CLICK/SEE; screenshots; **do not close** the browser mid-run so the user can watch/correct |
| `ar-qa-api-apidocs` | API testing via AR **apidocs** (Try-it) and/or Postman/HTTP collections |
| `ar-qa-db-readonly` | Connect to SQL Server (or named env DB) and run **SELECT-only** queries — no schema/infra changes, no writes |
| `ar-qa-ticket-evidence` | Ticket → plan → UI/DB/API evidence pack under `C:\WORK\qa-evidence\` |
| `product-desk-auto-route` | Route “test this ticket” style asks to **Qata** |
| Rule `ar-qa-cursor-native` | Prefer Canvas + skills + visible browser over a hosted Studio SPA |

## Live supervision surfaces

1. **Cursor Browser / headed desktop browser** — AR UI and apidocs stay open; action strip logged.  
2. **Cursor Canvas** — live QA board (checklist, params, pass/fail, narrated steps) beside chat.  
3. **Evidence folders** — screenshots, redacted JSON, Postman collection results (machine-local under `C:\WORK\qa-evidence\`).

## MCP / plugins used in practice

| Integration | Use |
|-------------|-----|
| `regnology-mcp` | Jira Cloud, Bitbucket (incl. doctrine-product), Confluence |
| Atlassian MCP | Alternate Jira/Confluence reads when configured |
| Postman plugin / MCP | Preferred for collection runs when OAuth sign-in works; otherwise local collection + session runner |
| Cursor Canvas / Browser tools | Supervision and UI/API visibility |

## Data flow (typical Qata ticket/API run)

```
User ask → auto-route / Hey Qata
    → read ticket (Jira MCP or browser)
    → Canvas + visible browser
    → UI / API / DB (read-only) as needed
    → evidence pack + verdict draft
    → user confirms before any Jira write
```

## What this does *not* change

- No replacement of Agile Reporter application infrastructure.  
- DB access is **query-only** against existing environments.  
- Product desk settings still come from `product-desk/product-desk.yaml` (Olga-owned).
